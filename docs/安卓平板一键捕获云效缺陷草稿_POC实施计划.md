# 安卓平板一键捕获缺陷：POC 实施计划

## 1. POC 结论目标

先验证“测试人员点击一次平板浮窗后，系统能稳定保留问题发生前后的现场证据”这一核心链路；**本 POC 不接入 AI，也不向云效创建正式缺陷**。通过后，再分阶段加入草稿生成和云效提交。

### 成功标准

- 测试人员在平板点击“报缺陷”后，电脑在录制收尾完成后的 **15 秒内**生成本地证据包。
- 证据包至少包含：触发截图、触发前 60 秒与后 10 秒的连续录像、logcat、设备/App 信息、UI XML（获取失败时必须有明确原因）。
- 在一台目标平板连续采集 30 分钟、随机触发 20 次的测试中，证据包完整且录像可正常播放的成功率不低于 **95%**。
- 断开网络、上传服务不可用或云效不可用时，证据仍完整保存在测试电脑本地。

## 2. POC 范围与非目标

### 范围

- 1 台 Windows 测试电脑 + 1 台真实目标安卓平板。
- 1 个被测 App、1 个测试环境和 1 个测试账号。
- 平板侧 Capture Agent：前台录屏、悬浮“报缺陷”按钮、触发事件上报。
- 电脑侧 Collector：设备连接检查、logcat 环形缓存、ADB 元数据采集、证据包生成与本地查看。
- 仅支持 USB ADB；Wi-Fi ADB、断线自动恢复可作为附加验证项。

### 非目标

- AI 自动写缺陷、OCR、根因判断、自动定级。
- 云效创建缺陷、附件上传、字段映射、服务端对象存储。
- 网络请求抓包、HTTPS 解密、绕过证书锁定。
- 多平板并发、企业权限体系和长期存储治理。

## 3. POC 使用流程

1. 测试人员以 USB ADB 连接平板，Collector 校验设备、被测包和剩余存储空间。
2. 测试人员在平板启动 Capture Agent，授予媒体投影和悬浮窗权限，点击“开始采集”。
3. Capture Agent 连续录制并仅保留最近 60 秒的视频片段；Collector 同时持续缓存 logcat。
4. 发现问题时，测试人员点击平板浮窗“报缺陷”。
5. 平板冻结触发前的录像、继续录制约 10 秒；Collector 立即采集截图、Activity、UI XML、设备/App 信息，并以触发点截取日志。
6. Collector 在视频收尾后生成本地证据包，并显示“成功/部分成功/失败”以及各项材料的状态。
7. 测试人员打开证据包，确认录像从触发前约 60 秒开始连续播放。

## 4. 最小技术架构

```text
安卓平板                                      Windows 测试电脑
┌───────────────────────┐                    ┌───────────────────────────┐
│ Capture Agent          │                    │ Collector                 │
│ - MediaProjection 录屏 │──触发事件─────────▶│ - ADB 会话与健康检查       │
│ - 10 秒视频分段环形缓存│   （USB 转发通道） │ - logcat 环形缓存          │
│ - 前台服务与浮窗按钮   │                    │ - 截图/UI XML/元数据采集   │
└───────────────────────┘                    │ - 视频拼接与本地证据包      │
                                               └───────────────────────────┘
```

### 通信约束

- POC 固定采用 USB ADB 通道。平板事件经 `adb reverse` 或 Collector 侧端口转发传至本机服务，避免依赖办公网连通性。
- 每次采集会话生成随机 `session_id`；事件包含单调时间、视频段序号和相对时间，不能只依赖两台设备的墙上时钟。
- 若事件通道失败，Collector 必须支持一个备用电脑快捷键触发，并在证据包中标注触发来源。

## 5. 关键实现约束

### 5.1 视频环形缓存

- 使用 `MediaProjection` 前台服务录屏；显式显示系统通知并处理授权撤销。
- 以 10 秒为一个片段，保留最近 6 段；触发后额外封存约 10 秒。
- **每个片段必须从关键帧开始**，或采用经验证可安全拼接的格式；这是 POC 的首要技术风险。
- 默认采用 720p 或 1080p、15–24fps 的可配置档位；以文字可读和稳定性优先，不默认追求原始分辨率。
- 触发后的视频必须形成约 70 秒的连续可播放文件；无法拼接时保留原片段并记录失败原因，不可静默丢失。

### 5.2 时间对齐

每个捕获事件与 manifest 至少记录：

- 平板单调时钟时间；
- Collector 收到事件的单调时钟时间；
- 视频分段序号及段内相对偏移；
- 截图时间、logcat 截取起止时间及时间来源。

这样平板与电脑的系统时钟漂移时，仍能校对录像、截图和日志。

### 5.3 ADB 采集

触发后，Collector 尝试采集：

- 当前截图：`screencap`；
- 当前页面：前台 Activity / window 信息；
- UI 层级：`uiautomator dump`；
- 设备属性：机型、Android 版本、分辨率、序列号哈希；
- App 信息：包名、`versionName`、`versionCode`；
- 日志：以触发点截取 `T-90s` 至 `T+30s`，并额外提取崩溃、ANR 线索。

所有命令均应设超时。单项失败不能阻断其他材料的封存；失败必须写入 manifest。

### 5.4 日志前提

POC 以 ADB 可读取的日志为基础，但不将“按包名完整获得业务日志”视为天然成立。被测 App 试点前应确认能够输出：关键业务状态、错误日志、崩溃/ANR 信息，以及可选的 `traceId` / `requestId`。这属于 App 可观测性建设，不能由 Collector 替代。

## 6. 证据包规范

```text
capture_id/
  manifest/
    manifest.json              # 时间线、哈希、采集状态、失败原因
  raw/
    replay.mp4                 # 触发前约 60 秒 + 后约 10 秒
    screenshot.png
    logcat.txt
    ui.xml
    device.json
    app.json
  derived/
    crash_excerpt.txt          # 可选：从原始日志提取，保留来源范围
```

`manifest.json` 至少记录：`capture_id`、`session_id`、触发来源、各时间基准、被测包、App 版本、设备序列号哈希、文件 SHA-256、采集状态、失败原因、Collector 与 Agent 版本。

原始材料只写入、不覆盖；任何未来的 OCR、脱敏或 AI 草稿均放入 `derived/` 或独立 `draft/`，并记录其来源与版本。

## 7. 验收用例

| 用例 | 预期结果 |
|---|---|
| 正常业务异常 | 截图、录像、日志、UI XML 和元数据齐全；录像连续可播放 |
| App 崩溃 | 录像保留；日志包含相关崩溃线索或明确标记未获取 |
| App ANR | 录像保留；日志包含 ANR 线索或明确标记未获取 |
| UI XML 获取失败 | 其余材料仍生成；manifest 标明超时或命令失败 |
| ADB 中途断开 | 已完成材料保留；状态为部分成功；不产生伪“成功” |
| 存储空间低于阈值 | 禁止开启新会话并给出可操作提示 |
| 连续 30 分钟、20 次随机触发 | 完整且可播放的证据包成功率 ≥95% |

除成功率外，记录：触发到事件抵达 Collector 的延迟、触发到证据包就绪耗时、视频连续可播放率、各材料的独立缺失率、CPU/内存/电量与温升。

## 8. 实施拆分（建议 5–8 个工作日）

### Day 1：技术预检

- 锁定平板型号、Android 版本、被测 App 和测试账号。
- 验证 MediaProjection 可持续录屏 30 分钟；确认分段文件编码、关键帧和合并方案。
- 验证 ADB 的截图、UI XML、Activity、版本信息和 logcat 可用性。
- 确定 USB 事件通道与本机监听端口。

**退出条件：** 能手工完成一次“录屏片段 + ADB 材料”的本地证据包。

### Day 2–3：平板 Agent

- 实现前台录屏服务、分段循环保留、授权失效提示。
- 实现悬浮按钮与含 `session_id`、段序号和单调时间的触发事件。
- 先输出原始片段，后处理为连续录像，避免在录屏链路中引入复杂拼接逻辑。

**退出条件：** 随机触发后可稳定找到正确的前后视频片段。

### Day 3–5：Collector

- 实现 ADB 设备状态、会话启动、logcat 环形缓存和触发采集。
- 实现视频拉取/拼接、目录生成、哈希和 manifest。
- 实现最小结果页：每种材料显示成功、失败或缺失原因，并可打开本地目录。

**退出条件：** 正常场景下端到端生成完整证据包。

### Day 6–8：稳定性验证与复盘

- 执行验收用例和 30 分钟/20 次随机触发测试。
- 记录失败样本，优先修复视频连续性、事件丢失、ADB 超时和磁盘保护问题。
- 输出 POC 报告，并决定是否进入 AI 草稿与云效集成阶段。

## 9. POC 通过后的下一阶段

只有 POC 达标后再加入下列能力：

1. 服务端对象存储、上传重试、访问控制和证据保留期限。
2. 文本、截图和录像的分级脱敏；原始录像默认不发送至外部模型。
3. 基于证据的 AI 草稿，严格区分“事实”“待确认项”和“定位线索”。
4. 云效适配器：先验证真实租户的授权、状态、必填字段、通知与附件限制，再开放人工确认后的正式提交。
5. 多设备、Wi-Fi ADB、自动重连、监控看板和运维治理。
